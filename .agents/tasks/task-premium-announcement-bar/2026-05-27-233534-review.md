# Premium announcement bar for Shopify Horizon theme

A custom section replaces the stock Horizon announcement bar with a feature-rich alternative supporting three display modes (fade slider, continuous marquee, static single-message), per-message icons via inline SVG, optional countdown timers, a progress bar synced to auto-rotation, and a localStorage-based dismiss. The implementation is split across a Liquid section (`sections/custom.liquid`), a vanilla JS controller (`assets/premium-announcement-bar.js`), a tiny countdown snippet, translation keys, and a `header-group.json` wiring file.

Watch for: the `shopify:block:select` editor event queries `data-block-id` but no slide ever renders that attribute (**confirmed**); countdown timer markup ships without any CSS (**confirmed**); no `shopify:section:unload` handler means instance cleanup never fires when the section is removed in the editor (**confirmed**); marquee and slider animations ignore `prefers-reduced-motion` (**confirmed**).

## High-level view

The section renders one of three layouts depending on `display_mode`. Slider uses a CSS grid with opacity crossfade and a JS-driven `setInterval` auto-rotate. Marquee duplicates all block markup in Liquid (for the seamless loop) and additionally in JS (`innerHTML` doubling), which means the DOM ends up with 4x the block content. Static simply hides all slides except the first via CSS alone.

The JS controller is a constructor-function prototype pattern, cleanly lifecycle-managed with a `destroy` method that tears down all event listeners and timers. However, the Shopify editor integration has a gap: `shopify:section:load` triggers re-init, but `shopify:section:unload` is never listened for, so removing the section from the editor leaks the instance.

Color integration offers two paths — Shopify's native `color_scheme` type with CSS variable fallback, or a manual override via `use_custom_colors` plus three color pickers. The dual-path is toggled in both Liquid class assignment and inline `<style>` variable definitions.

The countdown timer snippet is minimal — four `<span>` groups with `data-countdown-end` for JS pickup. But the `<style>` block in `custom.liquid` contains zero rules for `.sab-countdown*` classes, so the timer renders unstyled (inline spans with no spacing, sizing, or alignment).

## `shopify:block:select` dead-ends on missing attribute

The editor integration in `premium-announcement-bar.js` (line 419) looks for `slides[i].getAttribute('data-block-id') === blockId` to jump to the selected slide when a merchant clicks a message block in the editor sidebar. The slide elements in `custom.liquid` never emit a `data-block-id` attribute — they have `{{ block.shopify_attributes }}` (which produces `data-shopify-editor-block` markup) and `data-slide-index`, but nothing matching the JS query. The result: clicking a block in the editor never highlights the corresponding slide.

Fix: add `data-block-id="{{ block.id }}"` to each `.sab-slide` div in the slider loop (line 101 of custom.liquid). In the marquee loop, only the first set of slides (the "real" ones with `block.shopify_attributes`) need it.

## Countdown timer has no visual treatment

The snippet `announcement-countdown.liquid` renders `.sab-countdown` > `.sab-countdown__days` > `.sab-countdown__value` + `.sab-countdown__label`, but the `<style>` block in `custom.liquid` defines no rules for any of these classes. The elements will render as inline text with no spacing between segments, no font differentiation between value and label, and no alignment relative to the message text. Since the feature is exposed in the schema and ready to activate via the editor, shipping it without styling produces a broken-looking output for any merchant who enables it.

## Instance leaks on section removal

The `shopify:section:load` event correctly destroys and re-creates the instance. But `shopify:section:unload` (fired when a section is removed from the page) has no listener. The `destroy()` method exists and properly tears down timers and listeners, but it is never called in the unload path. In the theme editor — where merchants frequently add/remove sections — this leaks `setInterval` timers (auto-rotate and countdown) and a global `resize` listener per removal.

```js
// Missing handler:
document.addEventListener('shopify:section:unload', function(e) {
  var sectionId = e.detail ? e.detail.sectionId : null;
  if (!sectionId) return;
  var container = document.querySelector(
    '[data-premium-announcement-bar][data-section-id="' + sectionId + '"]'
  );
  if (container && container._premiumAnnouncementBar) {
    container._premiumAnnouncementBar.destroy();
  }
});
```

## Marquee DOM bloat from double duplication

The Liquid template renders each block twice inside `.sab-marquee-track` — once with `block.shopify_attributes` (the "real" slides) and once as an `aria-hidden` clone for seamless looping. This is a standard pattern for CSS-only marquees. However, `initMarquee()` in the JS (line 102) then executes `this.marqueeTrack.innerHTML = originalContent + originalContent`, doubling the entire track content again. The final DOM has 4x the original block count. For 10 messages (the block limit), that's 40 slide elements with full SVG icon markup each.

The Liquid duplication or the JS duplication should be removed — not both applied. Since the JS already handles it and also recalculates animation duration dynamically, the cleaner path is to remove the second `{%- for block -%}` loop in the Liquid marquee branch and let JS do the doubling.

## No respect for `prefers-reduced-motion`

Neither the CSS (`@keyframes sab-marquee-*`, opacity transitions on `.sab-slide`) nor the JS (auto-rotate interval, animation duration calculation) check for the user's motion preference. WCAG 2.3.3 (Animation from Interactions) and 2.2.2 (Pause, Stop, Hide) are relevant here. A `@media (prefers-reduced-motion: reduce)` block should disable the marquee animation and slider crossfade, and the JS should skip `startAutoRotate` when the preference is active.

## Undebounced resize on marquee recalculation

`initMarquee` attaches a raw `resize` listener that calls `_calcMarqueeDuration`, which reads `scrollWidth` and writes to `style.animation` on every event. During a window drag-resize this fires dozens of times per second, each triggering layout recalculation. A simple `requestAnimationFrame` gate or a 150ms debounce would prevent the thrashing without visible delay.
